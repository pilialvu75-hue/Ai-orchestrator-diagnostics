# Standalone relay — RV pilot, not deployed

This is an isolated Cloudflare Worker candidate, independent of Beta Access. The producer's GitHub credential stays server-side, scoped to this diagnostics repository only. No secret is present in the repository or APK. Use a randomly generated 32-byte pilot credential (64 lowercase hex characters) provisioned privately to the single tester; never embed it in an APK. This temporary pilot authentication is not a consumer enrollment solution. Production requires independent per-installation credential issuance, revocation and abuse controls.

The owner must provision a D1 database, copy wrangler.toml.example to wrangler.toml, set the real database ID, apply migrations, configure the secrets DIAGNOSTICS_GITHUB_TOKEN and RV_PILOT_TOKEN using the server secret store, and enable an explicitly approved HTTPS route. No deployment or paid resources are authorized by this PR. No GitHub token in user UI.

POST /v1/rendezvous/<configured-version>/report with Authorization: Bearer <pilot credential>, Content-Type: application/json. Accepts only schema 1 with 1..100 bounded typed events (UTC minute, component, event, optional elapsed_ms). No names, identifiers, descriptions, appointment contents, file paths or raw errors. Events older than 7 days or too far in the future are rejected. The receiver binds producer/version/platform to the route and configuration. This repository is public; explicit informed consent required before sending. IPs are not included in the archive; hosting infrastructure may still process connection metadata.

One release per RV version: diagnostics-rendezvous-v1-<version>. Immutable content-addressed asset rendezvous-diag-<sha256>.json. A 200 receipt is returned only after GitHub lists the exact asset with uploaded state, byte count and SHA-256 digest. If GitHub omits digest, fail closed. Retries reuse existing archive; no overwrites/deletion of assets or writes to other producers. D1 reserves up to 20 unique reports per UTC day and 200 per version, including failed reservations; test quota and provider limits before deployment. No automated rotation or deletion; owner must establish retention policy before production. A failed quota slot is not silently released. No raw request data stored in D1. No backend logs containing secrets.

Run node --test relay/test/worker.test.mjs. Tests use mock GitHub and D1, not a live receipt. Before RV integration, prove actual synthetic archive receipt at the approved deployed endpoint. No automatic client upload wired yet.
